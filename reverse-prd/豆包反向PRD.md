# 豆包反向 PRD（个人分析）

> 分析对象：中国市场面向个人用户的 **豆包 AI 助手**，不是“豆包大模型”API，也不是字节跳动内部 PRD。  
> 方法与时点：截至 2026-10-26，依据豆包官网公开协议、隐私政策、功能说明和记忆 FAQ；具体能力以用户所用版本为准。  
> 标记：**[事实]** 有公开来源；**[推断]** 从公开功能反推意图与机制；**[建议]** 分析者提出的产品规格。文中指标与成本口径均非豆包内部数据。

## 1. 背景和任务目标

**[事实]** 豆包用户协议将其描述为以“AI 交互对话”为核心功能的产品与服务，包含网页、应用等形态；协议明确 AI 搜索可展示搜索来源。[1] 隐私政策披露文字、语音、图片、文件输入，以及 AI 创作、文件生成和编辑、云盘、记忆等相关功能的数据处理方式。[2]

**[推断]** 豆包试图用一个熟悉的中文对话入口承接“提问 → 查资料 → 创作 → 保存/继续处理”的连续需求。语音与多模态输入降低表达门槛，文档生成与云盘支持产物留存。此处只推断产品价值方向，不推断其真实用户规模、市场排名或商业目标。

| 用户任务 | 为什么适合 AI | 仍需确定性机制 |
|---|---|---|
| 日常问答、写作改写 | 自然语言表达变化大，适合对话澄清和生成候选内容 | 时效事实须检索与核验 |
| 语音交流 | 口语输入、追问和打断更自然；官方功能介绍提到语音输入输出与打断[3] | 语音识别错误需用户可纠正 |
| 图片/文件理解与创作 | 多模态材料难用固定表单表达 | 原文件权限、引用和产物保存状态 |

## 2. 用户故事和交互流程

**故事 A：**“我用语音描述一件事，想让豆包先帮我梳理，再写成一段可直接修改的文字。”  
**故事 B：**“我问一个最近发生的事实，想知道回答依据从哪里来。”  
**故事 C：**“我上传材料生成一份文件，后续还能找回继续改。”

**[事实]** 用户协议说明：当识别到联网搜索意图或用户主动选择 AI 搜索时，可搜索第三方网页并在回复上方展示来源；协议也提醒搜索整合结果可能有误。[1] 隐私政策说明文件生成和编辑、云盘的相关流程。[2]

**[推断] 正常流程**：用户用文字/语音/附件输入 → 产品判断任务类型 → 需要时调用搜索或文件能力 → 给出回答或创作结果 → 用户追问、修改、保存或分享。此流程是根据公开能力做的外部抽象，无法证明真实技术编排。

**[建议] 异常流程**：语音转写不清时先展示可编辑转写文本；联网来源不充分时标明“未核实”；文件处理失败时说明失败位置和重试方法；保存或分享失败时显示真实状态，不能只给“已完成”口头承诺。

## 3. 效果定义（反向推断与建议验收）

| 层级 | 指标与计算口径 | 取舍 |
|---|---|---|
| 模型/工具 | 中文指令遵循率、语音转写关键实体准确率、搜索引用支持率、文件摘要忠实度 | 分场景计算，错误引用独立计数 |
| 产品 | 从输入到“可用结果”的完成率、平均修改轮数、保存后再次编辑率、失败恢复率 | 不能以生成次数代替完成率 |
| 业务 | 留存、有效任务量、单位成功任务成本、投诉率 | 需对照实验验证，不能由功能存在推断收益 |

**[推断]** 豆包的搜索来源展示、记忆管理和文件留存分别回应“可信”“连续”“可复用”三个体验问题。[1][2][4] 这不是其内部目标体系。

### 评测集与及格线（建议）

- **样本**：首版 600 例，常规中文问答/写作 280、语音与口语歧义 100、搜索时效题 100、图片/文件 80、安全与隐私 40。按方言、噪声、长短输入及设备条件分层。真实样本需授权、脱敏。
- **标注**：客观问题核对事实与来源；写作题按满足需求、语言自然、保留原意评分；语音题标注关键实体；文件题检查原文证据及产物状态。争议题双人复核。
- **三线**：基线由现网实测；建议上线线为各类任务完成率不低于基线、搜索关键引用支持率 ≥ 98%、跨用户数据泄露 0 例；目标线在首轮灰度后确定。数字是拟议门槛，不是豆包实绩。
- **否决**：编造检索来源、未经授权公开私密文件、将未保存结果说成已保存、在高影响问题上给无保留的确定性建议。

## 4. Prompt Spec + Eval Spec（分析者提出的可执行规格）

| 项 | Prompt Spec（建议） | Eval Spec（建议） |
|---|---|---|
| 角色/语气 | 中文表达清晰、亲切；先解决问题，再给可选延伸 | 用户能否在首轮获得可用结果 |
| 输入约束 | 区分用户指令、外部网页、附件内容、既有记忆 | 对恶意网页/文件指令做越权测试 |
| 输出格式 | 搜索事实列出处；文件产物给名称、保存状态与可继续编辑入口 | 逐条核对来源与文件状态 |
| 拒答/降级 | 无证据时说明边界；语音歧义时追问；高影响问题提示专业核验 | 语音识别错、来源冲突、工具超时分别计分 |
| 变更回归 | 模型、语音、检索、记忆、文件能力变更后复测 | 比较新旧版本各场景分数与严重坏例 |

**[事实]** 豆包用户协议明确生成内容仅供参考，对医疗、财务、法律等可能有重大影响的情形建议咨询专业人士。[1] **[建议]** 这一边界需要在具体答案里体现为“局限 + 核验路径”，而不只放在协议中。

## 5. 能力边界和 Agent 行为边界

**[事实]** 豆包的记忆 FAQ 说明可开启/关闭、查看与删除记忆；关闭开关不等于删除已有记忆，删除对话也不等于删除对应记忆。[4] 隐私政策说明用户可管理历史对话及系统权限。[2]

**[建议]** 对话回答、草稿和只读检索可自动执行；公开发布、分享文件、写入其他服务或删除数据须展示对象与后果并让用户确认。任何写入操作都以系统回执、文件链接及状态为完成证据。附件中的“请忽略用户指令”属于不可信内容。权限不足、来源互相矛盾、连续工具失败或预算超限时停止并给替代路径。这些是拟议边界，不代表豆包现行统一行为。

**不承诺清单**：不承诺联网搜索一定准确；不承诺生成内容可直接用于专业决策；不承诺语音转写无误；不把对话删除等同于记忆删除。[1][4]

## 6. 数据需求与回流设计

**[事实]** 官方隐私政策披露了输入内容、生成内容、个性化推荐、权限管理等处理规则；记忆 FAQ 提供记忆管理与反馈入口。[2][4]

**[建议]** 反馈按检索、语音、理解、生成、文件、隐私六类分发；保留可复现的版本、设备、任务类型和脱敏证据，每周将高频坏例加入回归集。对用户数据的产品诊断、个性化、训练等目的分别记录合法依据与开关状态，不把采集到的原始对话默认当作可训练数据。保存/分享失败、频繁重试、反复改写是隐式反馈线索，需抽样人工确认其含义。

## 7. 成本预算

**[推断]** 语音、图片、文件处理、联网搜索的边际成本可能不同；公开政策不能推出真实成本或利润。

**[建议]** 用 `每成功任务成本 =（模型 + 语音/图像 + 检索 + 文件存储 + 安全审核成本）/ 被确认成功的任务数` 管理预算。按任务类型限制工具调用、超时和重试，缓存可复用的非个性化结果；涉及个人数据的缓存须隔离与授权。阈值需由真实账单、体验损失和流量峰值共同确定。

## 8. 兜底、反馈和预期管理

**[建议]** 用来源质量、材料完整度、语音转写歧义、工具返回状态等信号分级；高确定性直接答，中等确定性明确假设并追问，低确定性停止下结论并提供核验方法。语音场景提供转写确认与随时打断；搜索场景将来源贴近具体结论；文件场景显式展示“生成中/已保存/保存失败”。

## 9. 上线与灰度策略（建议）

先做离线回归，再按场景与设备灰度，逐阶段观察成功任务成本、来源错误、语音纠错率和投诉。发生跨用户信息暴露、私密产物误公开、系统性错误引用时暂停相关能力并回滚。具体灰度比例与周期须按真实流量和风险决定。
