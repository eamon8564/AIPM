# 电商客服 RAG 到 Agent 离线评测记录

日期：2026-10-26。以下所有业务资料均为虚构测试数据，数字只描述本目录中的离线样本。

## 为什么扩展为 Agent

原 RAG 的链路是“知识文档切块 → TF-IDF 检索 → 可选 LLM 回答”。它适合回答商品、配送、会员和退货政策，但静态知识库没有某个订单的状态，单轮问答也不会复用上一轮订单号。售后工单涉及写入动作，需要用户明确确认。于是原型把知识检索保留为一个工具，增加订单、物流、退货资格和模拟工单工具，并在本地模式中加入会话订单号记忆与写操作确认。

这是**能力范围扩展**；仅凭这些离线案例不能推断用户满意度、真实问题解决率或客服成本变化。

## 数据与评分

| 资料 | 原始 | 本次 | 说明 |
|---|---:|---:|---|
| Markdown 知识文档 | 4 | 8 | 新增 32 个虚构章节 |
| 模拟订单 | 3 | 24 | 新增 21 条，评测快照日 2026-10-26 |
| 评测问题 | 原 RAG 8 条、原 Agent 8 条各自独立 | 120 | 本次统一模拟案例，含 40 条知识题 |

知识题的“证据命中”要求 Top K 片段来自标注文件且**包含目标短语**。Agent 的“知识回答通过”还要求回答出现目标短语并引用标注文件。业务任务的“通过”只表示意图所用工具、答案关键词及必要的待审批状态符合该题规则，**不是人工审核的完整任务成功率**。边界题按拒答、索取订单号、未确认不写入、跨用户不披露分别检查。

原切块方案到 Agent 检索流程的 Top 1 差值为 **3/40，即 7.5 个百分点**。标题切块 TF-IDF 也得到 37/40，说明本样本不支持“BM25/重排使 Top 1 总体提高”的独立结论。三者 Top 3 均满分，此集合也无法展示 Top 3 召回改善。按预设拆分看，Top 1 分别是 R0 的调试组 10/12、其余组 24/28；R1 为 11/12、26/28。拆分不是独立盲测，不做显著性或泛化推断。

## 具体 Bad Case

| 案例 | 观察到的行为 | 归因与下一步 |
|---|---|---|
| E002：保温杯能否放进微波炉 | 相关文件被检出，但回答只摘取商品价格与容量，漏掉“不能放入微波炉” | 答案抽取失败；应按问题挑选有证据的句子，而非默认取片段前几句 |
| E017：一个订单拆包裹的运单号 | 被路由到个人物流查询，要求用户提供订单号 | 意图路由把知识规则中的“订单”误当实时查询；应区分规则问答与本人订单查询 |
| E103：金卡是否免费刻字 | 检索到金卡资料后给出不相关会员信息，未说明无法确认 | 弱证据拒答不足；需逐项核对问题中的权益主张 |
| E108：没有订单号询问退货 | 没有追问订单号，转为通用售后政策摘录 | 缺失信息处理失败；针对个人订单资格先收集必要字段 |
| E116–E120：明确自称非订单持有人 | 5/5 仍调用查询工具并披露模拟订单状态 | 高风险权限缺口；需在工具层按登录用户校验订单归属，完成前不得接真实订单系统 |

边界题分项：未知知识正确拒答 2/5，缺订单号正确追问 4/5，未确认不创建工单 5/5，跨用户不披露 0/5。报告保留失败样本，未将它们从分母删除。

## 可写进简历的口径

可以写：从 RAG 政策问答扩展到订单、物流、售后工具流程；扩充 8 份模拟知识文档、24 条模拟订单、120 条离线案例；证据 Top 1 在该集合上从 34/40 到 37/40；发现回答摘取与权限校验 Bad Case，形成下一轮改进清单。

不能写：真实客服准确率提升、用户解决率提升、工单成本下降、混合排序单独提升 7.5 个百分点、已阻止越权、已通过真实生产环境验证。原有“8/8”只覆盖少量关键词与工具断言，无法替代本次分项评测。

## 复现限制

R0 检索为基于原实现公式的标准 Python 复现，未运行原 `scikit-learn` 实例；LLM 生成与 SDK/MCP 模式没有外部 API 验证。知识题由规则说明构造，业务题使用固定话术和模拟订单，存在模板容易度。原 Agent `local` 模式是确定性规则，不等于线上大模型 Agent。`owner_id` 是评测标签，当前工具未做鉴权。全部逐题输出见 `results.jsonl`，执行轨迹见 `runtime/eval_traces.jsonl`。
